## Purpose

We aim to capture the volume of engagement around different topics across the internet. We use public and private APIs to obtain data.

To most accurately measure attention, we prioritize active engagement over passive engagement and apply source-level weighting to down-weight signals susceptible to artificial inflation.

The methodology for our **general attention index** is shown below.

<Warning>
  The specific methodologies may vary depending on the market category. Be sure to check the methodology of each index before placing a trade.
</Warning>

## Data Collection

Raw metrics are aggregated at fixed intervals using keyword-based querying, log-transformed, and combined using pre-defined weights.

The keyword we use is the same as the name of the respective market. For example, the “Claude Code” market uses “Claude Code” as its keyword.

Most engagement data follows a power law. So, we apply a $ln(x+1)$ transformation on each metric to stabilize variance and mitigate the impact of outliers.

## Frequency

We collect data from each source at different frequencies. The index updates whenever new data arrives from any source. Sources that have not yet updated retain their most recent values until new data is received.

<Expandable title="example: index update">
  - **Source A** updates hourly
  - **Source B** updates daily
  - **Source C** updates weekly

  If **Source A** reports new data at 1:00 PM, the index updates immediately using:

  - the new value from Source A
  - the most recent values from Sources B and C

  When **Source B** or **Source C** later updates, the index updates again using their new values and the latest values from the other sources.
</Expandable>

## Sources

We integrate data in our general index from four primary platforms. All metrics are collected at fixed intervals and normalized to a 15-minute baseline to ensure consistency across different polling frequencies.

<Tabs>
  <Tab title="YouTube">
    ### **YouTube Data API v3 (Public)**

    - **Frequency:** Data collected hourly, normalized to 15 minutes (metrics divided by 4 pre-transformation).
    - **Discovery:** We use the `search.list` endpoint (`type.video`, `order.relevance`, `publishedAfter: t-24h`, `q={keyword}`) to obtain a list of the video IDs of the 50 most relevant videos published over the last 24 hours. This call also returns `totalResults`, which we use in our calculations below.
    - **Metrics:** We use the `videos.list` endpoint (`part.statistic`, `id={50 video IDs}`) to find `viewCount`, `likeCount`, and `commentCount`. We convert these integer returns into strings.

    We apply a $ln(x+1)$ transformation to each metric and then apply the following weights:

    | Metric         | Weight |
    | :------------- | :----- |
    | `totalResults` | 0.50   |
    | `commentCount` | 0.30   |
    | `likeCount`    | 0.15   |
    | `viewCount`    | 0.05   |

    We sum these metrics to score YouTube's contribution to the index.
  </Tab>
  <Tab title="Reddit">
    ### **Reddit API (Public)**

    - **Frequency:** Data collected hourly, normalized to 15 minutes (metrics divided by 4 pre-transformation).
    - **Discovery:** We use the `search` endpoint (`t=day`, `sort=top` ,`limit=100`, `q={keyword}`),  to obtain a paginated list with 100 posts per page.
    - **Metrics:** We paginate through results to count the total number of posts over the last 24 hours (`Total Posts`). For each post, we also count`ups` (upvotes), and `num_comments`. We sum total `ups` and total `num_comments` across all posts.

    We apply a $ln(x+1)$ transformation to each metric and then apply the following weights:

    | Metric         | Weight |
    | :------------- | :----- |
    | `Total Posts`  | 0.50   |
    | `num_comments` | 0.30   |
    | `ups`          | 0.20   |

    We sum these metrics to score Reddit's contribution to the index.
  </Tab>
  <Tab title="X (Twitter)">
    ### **TwitterAPI.io API (Paid)**

    - **Frequency:** Data collected every 30 minutes, normalized to 15 minutes (metrics divided by 2 pre-transformation).
    - **Discovery:** We use the `advanced_search` endpoint `query={keyword, time frame}`,`queryType="top"`), looking at posts over the last hour. This returns a paginated list with 20 results per page.
    - **Metrics:** We paginate up to 100 posts, summing `likeCount`, `replyCount`, and `retweetCount`across all posts.

    We apply a $ln(x+1)$ transformation to each metric and then apply the following weights:

    | Metric         | Weight |
    | :------------- | :----- |
    | `Total Posts`  | 0.50   |
    | `replyCount`   | 0.30   |
    | `retweetCount` | 0.15   |
    | `likeCount`    | 0.05   |

    We sum these metrics to score X's contribution to the index.
  </Tab>
  <Tab title="Google Trends">
    ### **SerpAPI Google Trends SDK (Paid)**

    - **Frequency:** Data collected hourly, not normalized.
    - **Standardization:** To eliminate volatility inherent in single-keyword Google Trends comparisons, we calibrate results for the keyword against four stable control terms: `ankle sprain`, `wrist pain`, `broken bone`, and `blurry vision`.
    - **Discovery:** We use the `search` endpoint with parameters`engine = google_trends`, `date = now 1-d`, and `q = {keyword}, ankle sprain, wrist pain, broken bone, blurry vision` . We use the averages returned for our calculations.

    <Steps>
      <Step title="Calculate Baseline">
        We take the simple average of the four control terms' averages.
      </Step>
      <Step title="Standardize Keyword">
        We divide the keyword's average interest by (baseline average + 1).
      </Step>
      <Step title="Calculate Final Metric">
        We apply a $ln(x+1)$ transformation to the result.
      </Step>
    </Steps>

      $$
      \ln\left(\frac{35.0}{1.0 + 1}\right) = \ln(17.5)
      $$

## Raw Combination

The **Raw Index** is the weighted combination of the Social Metrics and Google Trends, scaled by a factor of 10.

| Variable | Platform      | Weight              |
| :------- | :------------ | :------------------ |
| **G**    | Google Trends | 30%                 |
| **Y**    | YouTube       | 28% (40% of Social) |
| **R**    | Reddit        | 21% (30% of Social) |
| **X**    | X (Twitter)   | 21% (30% of Social) |

### Formula

$Raw\ Index = 10 \cdot [0.30G + 0.70(0.40Y + 0.30R + 0.30X)]$

<Expandable title="example">
  Suppose platform scores (post-transformation) are Y=`6.26`, R=`5.52`, X=`5.27`, G=2.92:

  1. Social Metric: `0.40(6.26) + 0.30(5.52) + 0.30(5.27) = 5.74`
  2. Preliminary Combination: `0.30(2.92) + 0.70(5.74) = 4.90`
  3. Raw Index: `4.90 × 10 = 49.0`
</Expandable>

## Final Index (EMA)

To reduce short-term noise, we smooth the Raw Index using an **exponential moving average (EMA)**. This dampens transient spikes while still allowing the index to respond quickly to sustained shifts in attention.

We use a **12-hour half-life**, meaning the weight of any single observation decays by half every 12 hours.

### EMA Update Rule

Each time new data arrives, the index updates as follows:

$$
Final\ Index = EMA_{t} = EMA_{t-1} + \alpha \cdot (Raw_{t} - EMA_{t-1})
$$

Where:

- `Raw_t` = the latest Raw Index value (see "Raw Combination" above)
- `EMA_{t-1}` = the previous smoothed index value
- `alpha` = the smoothing factor (see below)
- `dt` = time elapsed since the last update (in hours)

On first calculation, `EMA` is initialized to the current Raw Index value.

### Smoothing Factor

The smoothing factor `alpha` controls how much weight each new observation carries. It is derived from the half-life and the time between updates:

$$
\alpha = 1 - 2^{-(dt / halfLife)}
$$

**Currently**, the index updates every `dt = 0.5` hours (see "Frequency" above). With a `halfLife = 12` hours:

$$
\alpha \approx 0.028
$$

A smaller `alpha` means slower response to new data and a smoother index. In practice, ~2.8% of each update comes from the new Raw Index value, while ~97.2% carries forward from the previous EMA.

<Check>
  The final Attention Index is the EMA-smoothed value of a topic's weighted engagement across YouTube, Reddit, X, and Google Trends.
</Check>

<Expandable title="full worked example">
  Suppose we are calculating the index for the keyword "Claude Code" and the following raw metrics have been collected and normalized to 15-minute baselines:

  **Step 1: Platform Scores**

  After applying ln(x+1) transformation and per-metric weighting (see "Sources" above):

  - YouTube = `6.26`
  - Reddit = `5.52`
  - X = `5.27`
  - Google Trends = `2.92`

  **Step 2: Raw Combination**

  Using the formula: `Raw Index = 10 * [0.30G + 0.70(0.40Y + 0.30R + 0.30X)]`

  - Social Metric: `0.40(6.26) + 0.30(5.52) + 0.30(5.27) = 5.74`
  - Preliminary Combination: `0.30(2.92) + 0.70(5.74) = 4.90`
  - Raw Index: `4.90 × 10 = 49.0`

  **Step 3: EMA Smoothing**

  Assume the previous EMA value was `45.2` and `dt = 0.5` hours:

  - Smoothing factor: `α = 1 − 2^(−0.5/12) ≈ 0.028`
  - EMA update: `EMA = 45.2 + 0.028 × (49.0 − 45.2) = 45.2 + 0.11 = 45.31`

  The index moves from 45.2 → 45.31, absorbing only a small portion of the spike. If "Claude Code" sustains this higher level of attention over subsequent updates, the EMA will gradually converge toward the new Raw Index value.
</Expandable>
